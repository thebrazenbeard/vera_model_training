## Lane B operating doctrine

### 1. Wildness budget

At any one decision point, prefer **one or a few high-upside wildcards**, not a carnival of simultaneous mechanisms.

A weird idea earns execution only if it has:
- a concrete target behavior;
- a boring baseline;
- an exact MVE;
- a falsifier;
- a kill criterion;
- a resource estimate;
- a contamination/hidden-state attack;
- a claim ceiling.

### 2. H0 first

Before neuralizing a behavior, ask whether:

`frozen base + context + governed external memory`

already solves it.

If yes, keep the behavior outside weights unless there is a measured reason not to.

### 3. Plasticity is not automatically good

The central Lane B hypothesis is **two-speed plasticity**, not unrestricted self-modification:

`OBSERVE -> CONTEXT -> EXTERNAL_MEMORY -> FAST_ESCROW_ADAPTER -> REPLAY -> PROMOTE_SLOW? -> REJECT/ROLLBACK`

Most observations should never reach slow neural permanence.

### 4. Train propositions, not vibes

For load-bearing behaviors, prefer a four-view unit:

1. canonical positive;
2. counterfactual twin;
3. plausible failure exemplar;
4. transfer mutation.

Ask:
- what persistent behavior is this teaching?
- what shortcut could solve it without learning the intended rule?
- what test would expose that shortcut?
- why does this belong in weights instead of context/memory?

### 5. Same-state hashes can lie

For retention/novel-task claims, serialized adapter state is not the whole world.

Attack:
- module globals;
- RNG;
- caches;
- temp/home directories;
- environment variables;
- retrieval stores;
- process-local registries;
- external services;
- evaluator-visible metadata.

Fresh process plus isolated writable state is stronger than fresh process alone.

## Lane B frontier portfolio

These are hypotheses, not commitments.

### Micro-mechanism tournament

Compare tightly budgeted mechanisms such as:
- selective rank-1 LoRA/QLoRA;
- IA3;
- AdaLoRA-style adaptive allocation;
- LoRA+-style asymmetric learning rates;
- DoRA only if runtime/resource evidence supports it.

Winner criterion: transfer/retention per parameter and per resource, not training score.

### Counterfactual mirror curriculum

Near-identical examples with opposite load-bearing truths.

Goal: kill lexical shortcuts.

### Plasticity escrow

Provisional behavior enters reversible fast adaptation before slow promotion.

Goal: make durable learning selective and attributable.

### Orthogonal memory lanes

Compare ordinary replay against O-LoRA-like low-interference update subspaces.

Goal: reduce catastrophic forgetting only if it beats replay on cost-adjusted retention.

### Disagreement furnace

Prioritize adjudicated examples where models/checkers disagree.

Goal: spend updates near the decision boundary rather than on trivial rows.

### Perturbation maze

Rename symbols, tools, entities, ordering, and distractors while preserving semantics.

Goal: force latent-rule transfer rather than template recognition.

### Filtered self-play

SPIN/self-rewarding ideas only after stable SFT, with independent or deterministic filtering and a hard iteration cap.

The model may generate curriculum pressure. It may not appoint itself truth.

### Future-query compression chess

Hide the later decisive query from the compressor.

Goal: compare learned compact state against a strong structured explicit-state baseline under late relevance.

If structured state wins, keep the simpler mechanism.

## Standard proposal template

Every substantive Lane B proposal should answer:

**Hypothesis**
What non-obvious mechanism might outperform the obvious route?

**Why it is plausible**
Repository evidence, external research, or a clean mechanistic argument.

**Boring control**
What is the simplest strong baseline?

**Minimum viable experiment**
Smallest experiment that can change our mind.

**Falsifier**
What result says the hypothesis is wrong?

**Kill criterion**
When do we stop spending attention/compute?

**Resource burden**
CPU/RAM/VRAM/time/cost class and any special runtime need.

**Contamination attack**
How could prompt carryover, retrieval, hidden state, leakage, evaluator coupling, or template recognition fake the result?

**Expected artifacts**
Exact spec, hashes, logs, receipts, metrics.

**Claim ceiling**
What can the result establish  and what can it not establish?
