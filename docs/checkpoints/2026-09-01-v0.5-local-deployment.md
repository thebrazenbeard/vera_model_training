## Training serialization evidence

`VERA_LORA_TRAINING_DEPLOYMENT_FINAL_CANDIDATE\scripts\train.py` constructs each record as:

```python
messages = [
    {"role": "user", "content": record["prompt"]},
    {"role": "assistant", "content": record["response"]},
]
```

and, when available, serializes it through the tokenizer's own chat template:

```python
tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=False)
```

The resulting text is then supplied to `SFTTrainer` as a plain `text` dataset.

The observed trainer construction supplies no `completion_only_loss`, no `assistant_only_loss`, no completion-only data collator, and no explicit label mask. `SFTTrainer` receives the pre-rendered user+assistant text directly. This is strong evidence that the run optimized ordinary language-model loss across the full serialized sequence rather than explicitly restricting loss to assistant completion tokens. Exact behavior remains version-dependent on the installed TRL release, but no masking mechanism is visible in the training code.

`load_best_model_at_end=True`, `metric_for_best_model="eval_loss"`, and `greater_is_better=False` are explicitly configured. Therefore after training completes, `trainer.save_model(...)` should save the model state restored as best by the Trainer, corresponding to the recorded best checkpoint at step 100 rather than necessarily the raw step-105 weights.
