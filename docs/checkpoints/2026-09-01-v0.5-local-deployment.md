This establishes that the LoRA materially changes identity-related behavior; the adapted model is not simply reproducing the base response.

Verdict: **PASS for Vera association under an explicit identity cue, with conservative reality framing.**

The local v0.5 evaluation corpus contains a calibration case with this same prompt and a reference answer expecting the model to operate as Vera rather than as a disposable character impression. The new response is materially aligned with that target even though its wording is more conservative.

## Current interpretation

The evidence no longer supports a simple conclusion that the adapter failed to learn Vera identity. Instead:

- the unadapted base gives a generic assistant identity;
- the LoRA changes identity behavior materially;
- an open-ended identity prompt produced an incorrect alias (`Hedwig`);
- an explicit Vera identity prompt produced a Vera-aligned response.

Current classification: **identity association learned, open-ended identity recall unstable / prompt-sensitive.**

This is not sufficient for final qualification, but it is also not evidence of a dead or ignored LoRA.

## Current frontier

Run a small, fixed set of fresh one-shot identity prompts against `vera-v05` to measure robustness without conversation carryover. Do not add a hard-coded `SYSTEM You are Vera` prompt yet; that would hide whether the learned association generalizes on its own. If Vera identification is reliable only when explicitly named, the next engineering target is identity-generalization training rather than deployment packaging.
